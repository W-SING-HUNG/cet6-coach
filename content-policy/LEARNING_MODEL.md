# 学习模型（Learning Model）

本文件定义**一个学习者**如何被建模。目标不是学术完备，而是：
在数据稀疏的前提下，诚实地支撑**有用的下一步动作**。

适用范围：CET-6 单用户、长周期（数月）、每天几十分钟、观测机会有限。

---

## 0. 架构起点

**不从 IRT / BKT / 神经模型开始。**

初始架构 = **确定性证据台账 + 显式假设状态**。

理由（结合现实约束）：

- 这些模型都需要**群体数据或大量单用户观测**来估计参数。本项目两者都没有。
  在数据不足时拟合出的参数不是"粗略估计"，而是**无法证伪的数字**。
- 参数化模型的一个副作用是：它输出看起来精确的分数，
  而用户会据此做复习决策 —— 精确的错误比诚实的模糊更危险。
- 确定性台账的优点：每一条结论都能**指回具体观测**、能被人工检查、
  能在规则变化后重算、能整体回退。

**未来的升级条件是数据与可测收益，而不是技术的先进性**。

## 1. 信息层级

从"发生的事情"到"得出的结论"之间，有严格的分层。**跨层跳跃是主要错误来源。**

### A. PerformanceEvent（性能事件）—— 不可变的观测

记录**发生了什么**，不记录**为什么**。

概念字段：

- 试卷 / 内容 / 题目 id + **内容版本**（内容变更后旧事件不得被静默指向新内容）
- 大题 / 题型
- 用户响应（选项、文本、标为复习完成等）
- 正确性 / rubric 维度得分
- 题目级与大题级用时（有则记）
- **计时 / 不计时**
- **首次作答 / 复习作答**（两者证据价值不同，不可混同）
- 跳过 / 改过答案
- 可选的自信度自评
- 听力场景下的重放 / 分段行为（在支持后）
- 评分来源（本地规则 / AI / 人工）与其版本

不变式：**PerformanceEvent 里不出现"因为""说明他…"这类因果措辞。**
一旦允许在观测里写解释，后续所有统计都会把解释当成事实。

**不可变观测 vs 重新评分（重要）**

"事件不可变"指的是**原始事实**不可变，不是"分数永远冻结"：

- **不可变**：原始响应、作答序列、用时、交互事实（改答案、跳过、重放）、时间戳。
  这些是**历史事实**，任何后续处理都不得改写。
- **可版本化**：事件发生时产生的**评分结果**（正确性、rubric 得分）
  可以随事件一同存储，但必须带**评分者标识 / provider / 版本**来源。
- **重新评分不得覆盖历史观测**：当日后的 rubric 修订、模型升级、
  AI provider 更换导致同一份作答被重新评价时，**追加一条新的评估结果
  （或新的派生证据），保留原有的那一条**，而不是就地替换。
- 需要记住："这个学习者在当时被判定为 X"与"用今天的标准回看同一份作答是 Y"
  是两个不同的事实，都可能是真的。

理由：若允许覆盖，一次 AI provider 升级就会**静默重写历史** ——
过去的学习者状态、干预效果与迁移验证结论会在无人察觉的情况下改变，
而门禁要求 AI 派生的判断必须可追溯。

本阶段**不设计数据库 schema**。

现状映射：`answer_attempt`、`study_session`、`diagnostic_answer` 已承载大部分字段；
缺**计时与否、首次/复习、跳过/改答案**等区分 —— 这是后续阶段要补的观测维度。
另：当前 `answer_attempt` 的 `score` / `correct` 是就地写入、无评分者版本，
因此**尚不满足**上述可版本化要求 —— 记为差距，不在本阶段改。

### B. EvidenceSignal（证据信号）—— 派生的局部事实

例子：答错、慢而正确、快而错、重复出现的同一模式、
证据定位与选项不匹配、选项选择模式。

规则：

- **时间是证据，不是诊断。** "用了 18 秒"是事实；"时间不够说明没读懂"是推断。
- **选了某个干扰项是证据，不保证映射到某个误解。**
  真实 CET 干扰项**不是为本系统的诊断目的而构造的**，
  因此"选了 B ⇒ 他混淆了 X 与 Y"这一步在缺少独立验证时不成立（见 EVIDENCE_BASE 第 10 条）。

### C. MechanismHypothesis（机制假设）

概念字段：

- `mechanismId`（来自第 5 节的分类）
- `scope`（作用范围：哪个模块、哪类材料、是否跨模块）
- `direction`：`deficit`（缺陷）/ `unstable`（不稳定）/ `strength`（优势）
- `supportingObservations`：支持它的观测（引用具体事件）
- `contradictingObservations`：与之矛盾的观测
- `evidenceStage`：证据成熟度（见第 2 节）
- `lastObserved`：最后一次相关观测的时间
- `source`：`deterministic_rule` / `ai_suggestion` / `human_manual`
- `explanation`：人话解释"这个假设认为发生了什么"
- `uncertainty`：不确定性描述（缺什么证据、什么会推翻它）

关键设计：**`contradictingObservations` 是一等字段，不是可选备注。**
一个只能累积支持证据的结构，会在第一次遇到反例时整体失效，
或者在更糟的情况下继续维持错误结论。反例是假设能否存活的关键输入。

### D. LearnerStateClaim（学习者状态主张）

只有在证据支持时才能从假设提升而来。**可修订、可回退。**

要求：

- 每条主张必须携带其依据的假设 id 与证据成熟度。
- 主张的"等级"（如 mastered）不得高于其证据成熟度（见第 2、3 节）。
- 反例出现时，主张**必须**能降级。不能降级的主张不是测量，是标签。

### E. Intervention（干预）

每一次干预必须**完整指定**下列各项，缺任何一项的干预不允许下发：

- 目标机制
- 触发它的证据
- 协议（具体做什么、几轮、用什么材料）
- 成功判据（什么算通过）
- 时间预算（预计分钟数）
- 复测计划（延迟多久、用什么材料）
- 迁移计划（在哪些未触碰真实材料上验证）
- 停止 / 毕业规则（达到什么条件就不再练它）

最后一条最容易被省略，也最容易被用户感知为"无底洞"。
**没有毕业规则的训练计划会无限期占用时间预算。**

### F. 验证事件（Validation）

必须把四种验证**分开**，它们回答不同问题：

- **即时判据检查**：刚做完干预，能否达标？（最弱证据）
- **延迟复测**：隔一段时间再来，是否还记得、还会用？
- **迁移检查**：在**新的、未触碰过的真实 CET 材料**上是否成立？
- **计时 / 考试条件验证**：在有时间压力、不可回看、一次成型的条件下是否成立？

四者是递进的证据强度。**用前者的结果冒充后者，是最常见的自我欺骗形式。**

## 2. 证据成熟度阶梯

用**定性语义**，不用伪精确的概率数值。

| 级别 | 名称 | 含义 |
| --- | --- | --- |
| E0 | `UNASSESSED` | 没有可用证据。**不是弱项，是未知。** |
| E1 | `SIGNAL` | 一条或一条弱信号；够启动调查，**不够给学习者贴标签**。 |
| E2 | `CONVERGING` | 重复或三角互证的证据支持同一假设。 |
| E3 | `DELAYED_SUPPORTED` | 干预后通过延迟复测，有初步的保持证据。 |
| E4 | `TRANSFER_SUPPORTED` | 在**新的未触碰真实材料**、在相关约束下，表现出目标行为。 |

规则：

- **不是心理测量学概率。** 这些标签描述"证据结构"而不是"能力概率"。
- **可以回退。** 新反例出现时级别下降是正常的、健康的。
- **E3 / E4 不是永久掌握。** 长期不接触后回落是预期行为，不是系统故障。
- **计时与不计时的稳定性可能不同。** 不计时下 E4 不自动推出考试条件下也成立。
- **不得把任意样本数伪装成科学结论。** "连续答对 5 题即为掌握"这类阈值，
  如果不写明依据，就是编造的精确性。

## 3. 掌握度语义

**掌握不等于**：答对一次、看懂了讲解、刚复习完能复述、在原文上做对。

强证据需要三者兼具：**判据成立 + 延迟之后 + 迁移到新材料**，
理想情况下还要加上**在目标时间条件下成立**。

对应到证据级别：`E4` 才接近"掌握"；`E3` 是"初步稳定"；`E2` 及以下只能是"待验证假设"。

用户可见语义必须与级别对齐。把 `E2` 显示成"已掌握"是产品在说谎。

## 4. 诊断警示规则

以下每一条都是硬约束。它们的作用是**阻止从稀疏观测跳到自信结论**。

- **一个错误答案 ≠ 根本原因。** 它只是一个错误答案。
- **一个干扰项 ≠ 已确认的误解**，除非"干扰项 → 认知原因"这个映射本身已被验证。
  真实 CET 干扰项不是为本系统的诊断而构造的。
- **一次慢速响应 ≠ 工作记忆失败。** 慢可能是没读懂、可能是犹豫、可能是被打断、
  可能是谨慎复核。区分这些需要专门证据。
- **一次快速错误 ≠ 一定粗心。** "快"与"粗心"之间没有天然等价关系。
- **群体相关 ≠ 这个学习者的因果解释。** 词汇量与阅读能力在人群中相关，
  不代表某一道题答错的原因就是词汇（见 EVIDENCE_BASE 第 7、9 条）。
- **AI 的解释 ≠ 学习者状态事实。** 它是一条假设，来源标为 `ai_suggestion`。
- **没有证据 ≠ 弱点。** `E0` 必须是中性状态，不能落进低分或红色警示。

## 5. 机制分类 V1

保持**分层且有限**。分类的作用是让"练什么"可落地，不是穷举语言学。

原则：一个机制必须**可干预**（存在一种训练能改变它）且**可观测**
（存在某类证据能区分"有它"与"没它"）。不满足这两条的条目不应进入分类。

### 5.0 mechanismId 不变式

**`mechanismId` 是全局唯一、稳定的持久化标识符。**

- 全部 ID 采用 `<域>.<机制>` 的**命名空间**形式（`vocabulary.` / `reading.` /
  `listening.` / `writing.` / `translation.`）。
- 命名空间是必需的，不是风格偏好：同一机制名可能出现在不同域中
  （例如 `reading.distractor_discrimination` 与
  `listening.distractor_discrimination` 是**两个不同的机制**）。
  若用裸名持久化，两条假设会在同一张表里**碰撞成一条**，
  而它们的证据、干预与迁移路径完全不同。
- **ID 一旦写入即不得静默改换用途。** 显示标签（中文说明）可以修改；
  ID 本身若需变更，必须是一次显式的迁移，而不是就地复用。
- 未在本节登记的机制不得以临时 ID 落库。

本阶段**不实现枚举或 schema**。

### 5.1 跨模块词汇（`vocabulary.`）

- `vocabulary.lexical_recognition`（识别）
- `vocabulary.lexical_retrieval`（提取）
- `vocabulary.contextual_disambiguation`（语境消歧）
- `vocabulary.collocation_chunking`（搭配组块）
- `vocabulary.morphology_word_family`（构词与词族）
- `vocabulary.lexical_automaticity`（自动化）

词汇跨阅读、听力、写作、翻译出现，因此**不属于任何单一模块**。
但"词汇是问题"这个结论本身也不够——必须落到上面某一项才能设计干预。

### 5.2 阅读（`reading.`）

- **基础层**：`reading.lexical_access`（词汇通达）、`reading.syntactic_parsing`（句法切分）
- **篇章层**：`reading.referent_tracking`（指代追踪）、
  `reading.discourse_relation`（篇章关系）、`reading.viewpoint_stance`（立场与视角）
- **任务推理层**：`reading.question_intent`（题干意图）、
  `reading.evidence_localization`（证据定位）、`reading.paraphrase_mapping`（同义转述映射）、
  `reading.inference_boundary`（推断边界）
- **选项决策层**：`reading.distractor_discrimination`（干扰项辨别）、
  `reading.overgeneralization`（过度概括）
- **执行层**：`reading.pacing`（节奏）、`reading.answer_change_instability`（改答案的不稳定）

### 5.3 听力（`listening.`）

- **自下而上**：`listening.acoustic_lexical_access`、
  `listening.segmentation_connected_speech`（连读切分）、`listening.lexical_syntactic_parsing`
- **篇章层**：`listening.entity_referent_tracking`、`listening.discourse_structure_markers`、
  `listening.detail_retention`、`listening.stance_inference`
- **任务/决策层**：`listening.question_option_mapping`、
  `listening.distractor_discrimination`
- **策略层**：`listening.prediction`、`listening.monitoring_recovery`（察觉听不懂并恢复）
- **执行层**：`listening.pacing_attention`

**硬性提醒：不得随手标注"working memory deficit"。**
听力理解困难最常见的相关因素是**语言知识**而非认知特质（见 EVIDENCE_BASE 第 8 条）。
要下这类结论需要专门设计的、独立于语言知识的证据。当前系统没有这种工具。

### 5.4 写作（`writing.`）

- `writing.task_fulfillment`
- `writing.content_argument_development`
- `writing.organization_coherence`
- `writing.cohesion_reference`
- `writing.lexical_appropriacy_collocation`
- `writing.grammar_accuracy_control`
- `writing.syntactic_control_complexity`
- `writing.fluency`
- `writing.mechanics_register`

**语法检查器不等于专家写作辅导。** 只做语法纠错的"批改"覆盖不到写作的多维性
（见 EVIDENCE_BASE 第 12、13 条）。

### 5.5 翻译（`translation.`）

- `translation.source_proposition_segmentation`（命题切分）
- `translation.semantic_fidelity`（语义忠实）
- `translation.information_completeness`（信息完整）
- `translation.structural_reexpression`（结构重组）
- `translation.terminology_lexical_appropriacy`
- `translation.grammar_syntax`
- `translation.cohesion_readability`
- `translation.register_appropriateness`

**一份参考译文是证据，不是唯一正确译法。** 与参考译文的差异不等于错误，
除非该差异落在语义忠实或信息完整维度上（见 EVIDENCE_BASE 第 15 条）。

## 6. 使用真实内容的干预

干预必须锚定真实真题材料。**不做合成 CET 题。**

- **证据定位训练**：在真实篇章上反复练习"题干 → 原文证据句"的定位
- **真实干扰项对比**：用真题的原始选项做辨别训练，解释每个干扰项"错在哪一步"
- **真实句子句法/意群切分**：对真题原文的长句做显式切分
- **真实转述对齐**：把题干/选项与原文的转述关系显式标出
- **真实音频与文字稿对齐**：用真题音频做精听、跟读、分段复述
- **真实音频分段回忆**：听一段、复述、核对文字稿
- **写作修订**：对真实题目的学习者作答做分层修订（结构 → 论证 → 语言）
- **翻译命题映射与修订**：对真题原文做命题切分，再与学习者译文逐块对照

### 保留集策略

三种概念角色，**必须物理上可区分**：

1. **训练材料**：可以反复接触、可以讲解、可以拆解。
2. **迁移验证材料**：用于验证"在新材料上是否成立"。
   使用后其"未触碰"身份即失效。
3. **模考保留**：留到最后做整卷计时模拟。

约束：**不得为了让界面/看板显得活跃而消耗未触碰材料。**
训练池与模考保留由使用者自行设定，系统不代为决定。
未触碰材料的数量是**有限资源**，不是可用余额。

## 7. 调度与优先级

**必须把"题目记忆调度"与"机制掌握"分开**，它们是两个不同的对象。

- **题目记忆**：单个条目（某题、某个词）"何时再出现"。
  未来可由 FSRS 承担；当前是固定间隔（字段已预留）。
- **机制掌握**：某个机制是否稳定可用。它需要的是**更广的证据 + 迁移验证**，
  而不是把同一道题多推几次。**刷同一道题的复习间隔不会产生迁移证据。**

优先级排序可考虑：考试相关性（模块分值）、证据阶段与严重度、
期望收益、时间成本、保持风险、不确定性削减价值、保留集成本、距考试的时间跨度。

**在数据支持之前不做不透明 ML。** 排序依据必须可读、可复核、可解释。

## 8. 四个示例流程

每个示例都显式展示**拒绝过度诊断**的那一步。这是本模型与"错题本 + AI 解析"的分界线。

### 8.1 阅读错误

**观测**：仔细阅读某题选错，用时明显长于该组平均；同时另一题在原文有明确同义转述处答对。

**假设（初始）**：`reading.evidence_localization` 缺陷（方向 `deficit`，证据级别 `E1`）。
**明确拒绝**：不写"他词汇量不足"（人口相关不能作为本题因果），
不写"他选了 B 所以混淆了 X 与 Y"（干扰项映射未验证），
不写"他阅读速度有问题"（单题慢速不足以支撑）。

**干预**：在该真题篇章上做证据定位训练 —— 给出题干，只要求标出证据句，不要求选项；
随后核对标注，记录"定位偏差的类型"（找错段落 / 找到相关句但非决定性句 / 定位正确但选项解读越界）。

**延迟复测**：两天后，同机制、换段落，做同样任务。

**迁移检查**：在**另一份试卷**的未做过篇章上做一次完整作答，
观察定位行为是否改善（而不只是"这次对了"）。

**拒绝过度解读**：即使迁移检查通过，结论也只到"该机制在新材料上表现改善"，
不到达"他的阅读能力提高了"或任何分数预测。

### 8.2 听力错误

**观测**：听力某题选错；该处音频存在连读与弱读；同组另一题（信息密度低）答对。

**假设（初始）**：`listening.segmentation_connected_speech` 或
`listening.acoustic_lexical_access`，
两条假设**并列保留、不合并**（当前证据无法区分"没听出词"与"听出了词但没切对意群"）。
**明确拒绝**：不写"工作记忆不足"；不写"注意力不集中"；
不写"听力词汇量不够"（与阅读词汇量是两个不同问题，需要独立证据）。

**干预**：该段音频的**分段精听 + 文字稿对齐**：先盲听复述，再看文字稿标出"听错/漏听"的位置，
最后回到音频确认。文字稿来自第三方整理（已在 provenance 披露），不作为权威判据。

**延迟复测**：三天后，同段音频不同小节。

**迁移检查**：在另一份试卷的未听过音频上，检验同机制是否改善。

**注意当前状态**：听力诊断本身仍是 `unassessed`（诊断环节无音频刺激）。
因此上述流程属于**后续训练阶段**的模型，当前不可执行——不得因为"模型已写下"
就把听力当作已评估模块参与加权。

### 8.3 写作反馈

**观测**：真实题目作文，字数达标；结构完整但两个分论点都是抽象论述；
衔接词充足；存在少量语法错误。

**假设（初始）**：`writing.content_argument_development` 缺陷（`E1`）
+ `writing.grammar_accuracy_control` 不稳定（`E1`，因为错误数量少、分布零散）。
**明确拒绝**：不写"词汇贫乏"（无词汇多样性证据）；
不写"逻辑能力不足"（那是认知标签，不是可干预机制）；
不因语法错误就断定"语法差"（语法检查器不是写作能力测量）。

**干预**：对**同一篇**真实题目的作答做两轮修订 ——
第一轮只补具体例证/数据，第二轮才处理语言；对比修订前后的论证具体度。

**延迟复测**：五天后，新的真实题目（换话题），检查是否自发使用具体例证。

**迁移检查**：在**未做过的**真实写作题上，按考试条件限时完成，检查同一机制。

**拒绝过度解读**：AI 批改（或本地 stub）的分数变化不作为掌握证据。
AI 反馈在本产品中是补充性的，且必须与教学流程结合（见 EVIDENCE_BASE 第 14 条）。

### 8.4 翻译反馈

**观测**：真实中文原文翻译，关键信息点覆盖较好，但出现两处：
一处中文长句被译成并列的多个短句导致主次关系丢失；
一处专有名词使用了非通用译法。

**假设（初始）**：`translation.structural_reexpression` 缺陷（`E1`，仅一处实例）
+ `translation.terminology_lexical_appropriacy`（`E1`）。
**明确拒绝**：不写"翻译能力弱"（维度级标签越过证据）；
不因与参考译文不同就判错（参考译文不是唯一正确译法）；
不写"中文理解有问题"（命题切分正确说明理解到位）。

**干预**：对**同一段**真实原文做命题切分 → 标出每个命题的主次关系 →
只重写该长句，直到主次关系在英文中成立。

**延迟复测**：三天后，另一段含长句的真实原文（同机制）。

**迁移检查**：在**未做过的**真题翻译段落上，检查主次关系是否稳定保留。

**拒绝过度解读**：单次专有名词错译只记为 `E1` 信号；
在第二次出现同类问题前，不建立"专有名词是系统性问题"的结论。

## 9. 与当前实现的关系

本文件是**概念模型**，不是当前实现说明。当前实现（`src/domain`、`src/services`）是它的**早期近似**：

| 本模型 | 当前实现 | 差距 |
| --- | --- | --- |
| PerformanceEvent | `answer_attempt` / `study_session` / `diagnostic_answer` | 缺计时与否、首次/复习、跳过/改答案等区分 |
| EvidenceSignal | 未实现 | 无派生信号层 |
| MechanismHypothesis | 未实现；`Weakness` 是维度级近似 | 无机制粒度、无反例字段、无来源标注 |
| LearnerStateClaim | `SkillState` / `DimensionResult` | 粗粒度（skills/dimensions + score/mastery/confidence） |
| 证据成熟度 E0–E4 | `AssessmentStatus` 三态 | 三态是它的弱化版：只区分"有无证据"，不区分级别 |
| Intervention | `StudyTask` / `Recommendation` | 无成功判据、无复测计划、无迁移计划、无毕业规则 |
| 验证事件 | 未实现 | 无延迟复测与迁移验证机制 |
| 机制分类 | 未实现 | 无机制标识 |
| 保留集三分类 | `paper_study_state.pool`（训练池 / 模考保留） | 缺"迁移验证"这一角色 |

### 9.1 遗留实现不匹配（本阶段登记，不改运行时）

- **`AIGradingProvider.generateQuestions()`**
  （`src/ai/provider.ts` + `src/ai/providers/local-stub.ts`）：
  与新内容政策冲突（政策禁止 AI 生成 CET 评估/训练题）。实测**无任何调用方**。
- **`src/content/diagnostic-bank.ts`（合成诊断题库）**：
  文件自述为"诊断题库（原创内容，版本化 seed data）"，
  含面向学习者的原创词汇/阅读/写作/翻译题目与篇章，**没有一份来自真实历年真题**。
  作为早期阶段的临时措施可以理解（当时真题库为空），但它与
  `content-policy/PRODUCT_PRINCIPLES.md` 第 6 节的硬规则冲突。
  **关键约束**：这些原创题产出的作答**不得**被提升为新机制模型的权威证据。
  这条张力如实记录在此，不做粉饰。
- **`src/content/practice-library.ts`（合成练习库）**：
  同样自述为"原创，版本化 seed data"，含面向学习者的阅读篇章、词汇组、
  写作题与翻译题，其中听力条目还声明需要"原创英文对话音频"等**尚不存在的自制资产**。
  与上条属同一类不匹配，同样如实登记。

这三项都不是本阶段要修的东西，但**必须被登记**，否则 Expert Training System
会在不知情的情况下把合成内容当作真实评测证据使用。

**本阶段不改运行时。** 差距记录在此，作为 Expert Training System 阶段的输入。
诊断当前是**方向性的**，不是 CET 分数预测；听力诊断 `unassessed`；
复习间隔固定；写作/翻译为确定性本地 stub —— 这些现状都在 `README.md` 的
「已实现 / 未实现」两节中如实登记。
